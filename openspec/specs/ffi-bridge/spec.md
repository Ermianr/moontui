# ffi-bridge

Complete C ABI surface between Rust core and TypeScript bindings.

## Overview

The FFI boundary uses `bun:ffi` (or `node:ffi` where compatible). All communication is via direct function calls with primitive types and opaque pointers. No JSON, no serialization, no global state.

## Pointer Types

All pointers are branded opaque handles. Each pointer carries a phantom type parameter indicating what it points to. The brand is a `declare const` `unique symbol` that is erased at runtime — zero performance cost.

The TypeScript mapping layer SHALL use the branded `Pointer<T>` type for all FFI function signatures instead of raw `number`.

```typescript
declare const pointerBrand: unique symbol;
export type Pointer<out T = void> = (number | bigint) & { readonly [pointerBrand]: T };
```

Specialized pointer types:
- `Pointer<Renderer>` for renderer handles
- `Pointer<Buffer>` for buffer handles
- `Pointer<void>` for raw memory pointers (char*, u8*, etc.)

A `toPointer<T>(value: number | bigint): Pointer<T>` helper inside `ffi.ts` converts raw FFI return values. This helper is internal and not exported.

#### Scenario: Branded pointer rejects raw numbers
- **WHEN** a function expects `Pointer<Renderer>` and receives a raw `number` argument
- **THEN** TypeScript SHALL produce a compile-time type error

#### Scenario: Branded pointer accepts valid pointer
- **WHEN** a function expects `Pointer<Renderer>` and receives a value from `toPointer()`
- **THEN** no type error occurs
- **AND** the brand is erased at runtime (zero-cost abstraction)

#### Scenario: Different pointer types are distinguished
- **WHEN** a function expects `Pointer<Renderer>` and receives a `Pointer<Buffer>`
- **THEN** TypeScript SHALL produce a compile-time type error

#### Scenario: Pointer type is exported
- **WHEN** a consumer imports `Pointer` from `@moontui/core`
- **THEN** they SHALL receive the branded type `Pointer<out T = void>`

#### Scenario: Raw memory uses void brand
- **WHEN** a function returns a raw memory pointer (e.g., `bufferGetCharPtr`)
- **THEN** the return type SHALL be `Pointer<void>`
- **AND** consumers MAY cast it to the appropriate typed pointer

## C ABI Exports (Complete List)

The C ABI surface SHALL be defined by `#[moontui_export]` annotations in Rust source code instead of manual `extern "C"` functions in `lib.rs`. The `target/moontui-schema.json` file SHALL be the authoritative list of all exports.

#### Scenario: All exports are annotated
- **WHEN** the Rust source is inspected
- **THEN** every `extern "C"` function that delegates to a Rust method SHALL have a corresponding `#[moontui_export]` annotation on the source method

#### Scenario: Manual exports are documented
- **WHEN** an `extern "C"` function cannot be generated by the macro (e.g., constructor, static function, multi-pointer)
- **THEN** it SHALL be annotated with `/// @ffi_manual` comment
- **AND** it SHALL still appear in `target/moontui-schema.json`

#### Scenario: Schema is the source of truth
- **WHEN** `target/moontui-schema.json` is read
- **THEN** it SHALL contain ALL FFI exports (both generated and manual)
- **AND** the TypeScript codegen SHALL generate bindings for all entries
- **AND** manual function entries SHALL include `manual`, `ts_body`, `ts_args`, and `ts_returns` fields
- **AND** struct entries SHALL include field names, types, offsets, size, and alignment

#### Scenario: Manual function entry format
- **WHEN** a manual function is exported
- **THEN** the schema SHALL contain:
```json
{
  "name": "get_terminal_size",
  "receiver": null,
  "params": [],
  "returns": "u64",
  "ffi_name": "getTerminalSize",
  "manual": true,
  "ts_body": "const size = normalizeU64(lib.symbols.getTerminalSize())\nreturn {\n  width: Number((size >> 32n) & 0xffffffffn),\n  height: Number(size & 0xffffffffn),\n}",
  "ts_args": "",
  "ts_returns": "{ width: number; height: number }"
}
```

#### Scenario: Generated function entry format (unchanged)
- **WHEN** a generated function is exported
- **THEN** the schema SHALL contain the standard fields without `manual`, `ts_body`, `ts_args`, or `ts_returns`

## Schema JSON format

The proc-macro SHALL emit `target/moontui-schema.json` with the following structure:

#### Scenario: Function entry format
- **WHEN** a function is exported
- **THEN** the schema SHALL contain:
```json
{
  "name": "rust_function_name",
  "receiver": "TypeName" | null,
  "params": [
    { "name": "param_name", "type": "u32|u64|f32|f64|bool|ptr|i32|i64", "role": "self|arg" }
  ],
  "returns": "void|u32|u64|f32|f64|bool|ptr|i32|i64",
  "ffi_name": "camelCaseExportName"
}
```

#### Scenario: Struct entry format
- **WHEN** a `#[repr(C)]` struct is exported
- **THEN** the schema SHALL contain:
```json
{
  "repr": "C",
  "fields": [
    { "name": "field_name", "type": "f64|u64|u32|u16|u8|bool|ptr", "offset": 0 }
  ],
  "size": 56,
  "alignment": 8
}
```

#### Scenario: Schema is valid JSON
- **WHEN** `cargo build` completes
- **THEN** `target/moontui-schema.json` SHALL be valid JSON parseable by `JSON.parse()`

## TypeScript FFI Mapping

The TypeScript FFI mapping SHALL use the platform facade (`platform/ffi.ts` or `platform/index.ts`) instead of importing directly from `bun:ffi`. All pointer values SHALL be passed to `lib.symbols.*` calls without casting to `number`. The `toPointer()` helper SHALL be used only on return values from native symbols, not on arguments.

```typescript
import { dlopen, FFIType, ptr, toArrayBuffer, JSCallback } from "./platform/index";

const lib = dlopen(libPath, {
  createRenderer: { args: [FFIType.u32, FFIType.u32], returns: FFIType.ptr },
  createTestRenderer: { args: [FFIType.u32, FFIType.u32], returns: FFIType.ptr },
  destroyRenderer: { args: [FFIType.ptr], returns: FFIType.void },
  setupTerminal: { args: [FFIType.ptr, FFIType.bool], returns: FFIType.void },
  restoreTerminal: { args: [FFIType.ptr], returns: FFIType.void },
  render: { args: [FFIType.ptr, FFIType.bool], returns: FFIType.void },
  resizeRenderer: { args: [FFIType.ptr, FFIType.u32, FFIType.u32], returns: FFIType.void },
  getCurrentBuffer: { args: [FFIType.ptr], returns: FFIType.ptr },
  getNextBuffer: { args: [FFIType.ptr], returns: FFIType.ptr },
  getTestOutput: { args: [FFIType.ptr, FFIType.ptr], returns: FFIType.ptr },
  resetTestOutput: { args: [FFIType.ptr], returns: FFIType.void },
  bufferGetCharPtr: { args: [FFIType.ptr], returns: FFIType.ptr },
  bufferGetFgPtr: { args: [FFIType.ptr], returns: FFIType.ptr },
  bufferGetBgPtr: { args: [FFIType.ptr], returns: FFIType.ptr },
  bufferGetAttributesPtr: { args: [FFIType.ptr], returns: FFIType.ptr },
  bufferGetRealCharSize: { args: [FFIType.ptr], returns: FFIType.u32 },
  bufferWriteResolvedChars: { args: [FFIType.ptr, FFIType.ptr, FFIType.usize, FFIType.bool], returns: FFIType.u32 },
  getRenderStats: { args: [FFIType.ptr, FFIType.ptr], returns: FFIType.void },
  setCursorPosition: { args: [FFIType.ptr, FFIType.i32, FFIType.i32, FFIType.bool], returns: FFIType.void },
  setEventCallback: { args: [FFIType.ptr, FFIType.function], returns: FFIType.void },
  processEvents: { args: [FFIType.ptr], returns: FFIType.usize },
  getTerminalSize: { args: [], returns: FFIType.u64 },
});
```

#### Scenario: No bun:ffi import in ffi.ts
- **WHEN** `packages/core/src/ffi.ts` is inspected
- **THEN** it SHALL contain zero imports from `bun:ffi`
- **AND** all FFI-related imports SHALL come from `./platform/index`

#### Scenario: Pointer passed directly to symbols
- **WHEN** `api.destroyRenderer(p)` is called
- **THEN** `p` (a `Pointer<Renderer>`) SHALL be passed directly to `lib.symbols.destroyRenderer`
- **AND** no `as number` cast SHALL be applied

#### Scenario: Pointer return values are normalized
- **WHEN** `lib.symbols.getCurrentBuffer(p)` returns a raw value
- **THEN** `toPointer()` SHALL convert it to a branded `Pointer<Buffer>`
- **AND** the branded pointer SHALL be the correct native type for the current runtime

#### Scenario: Boolean arguments are normalized via ffiBool
- **WHEN** `api.setupTerminal(renderer, true)` is called
- **THEN** the value `1` (from `ffiBool(true)`) SHALL be passed to native code
- **AND** `api.setupTerminal(renderer, false)` SHALL pass `0`

## Invariants

- All pointer arguments must be valid (non-null) unless documented otherwise.
- String arguments (`text`, `id`) are UTF-8 encoded and null-terminated where marked as `cstring`.
- Color arguments are pointers to 4 × `u16` arrays: `[r, g, b, a]` with 0-65535 range.
- `RenderStats` is an `extern struct` with C-compatible layout. TypeScript allocates it and passes a pointer.
