# ffi-error-signaling

Mechanism for propagating Rust `Result` errors across the FFI boundary to TypeScript as thrown exceptions.

## Requirements

### Requirement: FFI functions that fail return i32 error code
Functions that return `Result` in Rust SHALL return `i32` at the FFI boundary: `0` for success, `1` for error. The TypeScript wrapper SHALL check this return value and throw an `Error` with a descriptive message if non-zero.

#### Scenario: Successful operation returns 0
- **WHEN** a Rust method that returns `Result<(), io::Error>` succeeds
- **THEN** the FFI function SHALL return `0`

#### Scenario: Failed operation returns 1
- **WHEN** a Rust method that returns `Result<(), io::Error>` encounters an I/O error
- **THEN** the FFI function SHALL return `1`
- **AND** the error SHALL NOT cross the FFI boundary

#### Scenario: TypeScript throws on error
- **WHEN** a TypeScript wrapper receives a non-zero return from an FFI function
- **THEN** it SHALL throw an `Error` with a descriptive message identifying the failed operation

### Requirement: Manual FFI functions for error-returning methods
Methods that return `Result` SHALL be implemented as manual FFI functions in `lib.rs` with `/// @ffi_manual` annotation, not auto-generated by the proc-macro.

#### Scenario: Macro skips error-returning methods
- **WHEN** the proc-macro encounters a method that returns `Result` in `should_skip_method`
- **THEN** it SHALL skip generating an FFI wrapper for that method
- **AND** the method SHALL be listed in `should_skip_method`

#### Scenario: Manual FFI function handles null pointer
- **WHEN** a manual FFI function receives a null self pointer
- **THEN** it SHALL return `1` (error) without dereferencing the pointer

### Requirement: Error does not corrupt renderer state
If an I/O error occurs during `render()`, the buffer swap SHALL still occur to keep front/back buffers consistent.

#### Scenario: I/O error during render preserves buffer consistency
- **WHEN** `render()` encounters an I/O error during `write_all` or `flush`
- **THEN** the front and back buffers SHALL still be swapped
- **AND** the function SHALL return `1`
- **AND** subsequent render calls SHALL operate on consistent buffer state
