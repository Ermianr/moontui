# ffi-codegen

Automated FFI binding generation from Rust to TypeScript.

## Overview

A proc-macro `#[moontui_export` generates `extern "C"` wrappers and emits a JSON schema. A TypeScript codegen script reads the schema and generates `ffi.ts` (symbol definitions + api object) and `structs.ts` (declarative struct readers). This eliminates manual maintenance of `lib.rs` and hardcoded offsets in `ffi.ts`.

## Requirements

### Requirement: Proc-macro generates extern "C" wrappers
The `#[moontui_export]` proc-macro SHALL generate `extern "C"` wrapper functions for annotated methods in `impl` blocks. Each wrapper SHALL null-check the receiver pointer and delegate to the underlying Rust method.

#### Scenario: Simple method with no return value
- **WHEN** `#[moontui_export]` is applied to `impl CliRenderer { pub fn render(&mut self, force: bool) { ... } }`
- **THEN** the macro SHALL generate:
```rust
#[expect(unsafe_code)]
#[unsafe(no_mangle)]
pub extern "C" fn render(renderer: *mut CliRenderer, force: bool) {
    if renderer.is_null() { return; }
    unsafe { (*renderer).render(force); }
}
```

#### Scenario: Method with return value
- **WHEN** `#[moontui_export]` is applied to `impl CliRenderer { pub fn process_events(&mut self) -> usize { ... } }`
- **THEN** the macro SHALL generate an `extern "C"` function that returns `Default::default()` when the pointer is null

#### Scenario: Method name is auto-converted to camelCase
- **WHEN** `#[moontui_export]` is applied to a method named `setup_terminal`
- **THEN** the generated `extern "C"` function SHALL be named `setupTerminal`

#### Scenario: Custom FFI name override
- **WHEN** `#[moontui_export(name = "myCustomName")]` is applied to a method
- **THEN** the generated `extern "C"` function SHALL use `myCustomName` as the export name

### Requirement: Proc-macro generates schema JSON
The `#[moontui_export]` proc-macro SHALL write `target/moontui-schema.json` describing all annotated functions and structs. The schema SHALL be updated on every `cargo build`.

#### Scenario: Schema includes function definitions
- **WHEN** `#[moontui_export]` is applied to `impl CliRenderer { pub fn render(&mut self, force: bool) { ... } }`
- **THEN** `target/moontui-schema.json` SHALL contain:
```json
{
  "functions": {
    "render": {
      "receiver": "CliRenderer",
      "params": [
        { "name": "renderer", "type": "ptr", "role": "self" },
        { "name": "force", "type": "bool" }
      ],
      "returns": "void",
      "ffi_name": "render"
    }
  }
}
```

#### Scenario: Schema includes struct definitions
- **WHEN** `#[moontui_export]` is applied to `#[repr(C)] pub struct FrameStats { pub last_frame_time_ms: f64, ... }`
- **THEN** the schema SHALL contain the struct with field names, types, offsets, size, and alignment

#### Scenario: Schema includes manual functions
- **WHEN** a function is annotated with `/// @ffi_manual` comment
- **THEN** the schema SHALL include the function signature but SHALL NOT generate a wrapper

### Requirement: TypeScript codegen reads schema and generates bindings
A `scripts/generate-ffi.ts` script SHALL read `target/moontui-schema.json` and generate:
- `packages/core/src/ffi.ts` — `dlopen` symbol definitions and typed `api` object
- `packages/core/src/structs.ts` — `defineStruct` declarations for each struct

The callback factory section SHALL use declarative `CallbackDescriptor` data structures and a shared `emitCallbackFactory()` function, rather than hardcoded string concatenation. A `decodeStringPointer(ptr, len)` helper and a module-scoped `textDecoder` SHALL be emitted in the generated file.

#### Scenario: Codegen generates ffi.ts
- **WHEN** `bun run build:codegen` is executed and schema.json contains function definitions
- **THEN** `packages/core/src/ffi.ts` SHALL be regenerated with all functions from the schema
- **AND** the file SHALL start with `// AUTO-GENERATED by scripts/generate-ffi.ts — DO NOT EDIT`
- **AND** the codegen script SHALL NOT contain hardcoded `manualLibDefs` or `needsSpecialHandling` lists
- **AND** all manual function definitions SHALL be read from the schema's `ts_body`, `ts_args`, and `ts_returns` fields

#### Scenario: Generated ffi.ts contains decodeStringPointer helper
- **WHEN** `packages/core/src/ffi.ts` is generated
- **THEN** it SHALL contain a `decodeStringPointer(ptr: number, len: bigint): string` function
- **AND** it SHALL contain a module-scoped `const textDecoder = new TextDecoder()`

#### Scenario: Callback factories use decodeStringPointer
- **WHEN** `createEventCallback` or `createMouseCallback` is generated in `ffi.ts`
- **THEN** they SHALL call `decodeStringPointer(typePtr, typeLen)` instead of inlining `new TextDecoder().decode(backend.toArrayBuffer(...))`

#### Scenario: Callback setter signatures accept Pointer<void>
- **WHEN** `setEventCallback`, `setResizeCallback`, `setMouseCallback` are generated in `ffi.ts`
- **THEN** their second parameter type SHALL be `Pointer<void> | 0` (not `Pointer<Renderer> | 0`)

#### Scenario: injectMouseEvent reuses module-scoped textEncoder
- **WHEN** `injectMouseEvent` is generated in `ffi.ts`
- **THEN** it SHALL use the module-scoped `textEncoder` constant instead of creating `new TextEncoder()` inline

#### Scenario: Codegen reads manual function metadata from schema
- **WHEN** the schema contains a function with `"manual": true` and `"ts_body"` field
- **THEN** the codegen script SHALL use the `ts_body` to generate the TypeScript function implementation
- **AND** it SHALL NOT maintain its own parallel knowledge of the function's arguments or body

#### Scenario: Codegen uses declarative callback descriptors
- **WHEN** `scripts/generate-ffi.ts` is inspected
- **THEN** the callback factory section SHALL be generated from `CallbackDescriptor` data structures
- **AND** it SHALL NOT contain hardcoded `ffiContent +=` string concatenation for individual callback lines

#### Scenario: Codegen has no hardcoded function name lists
- **WHEN** `scripts/generate-ffi.ts` is inspected
- **THEN** it SHALL NOT contain a `needsSpecialHandling` array or similar hardcoded function name list
- **AND** it SHALL NOT contain a `manualLibDefs` object with hardcoded FFI type definitions
- **AND** all function metadata SHALL be derived from the schema

#### Scenario: Codegen generates structs.ts
- **WHEN** schema.json contains struct definitions
- **THEN** `packages/core/src/structs.ts` SHALL be regenerated with `defineStruct` declarations for each struct
- **AND** each struct SHALL have a corresponding TypeScript interface generated
- **AND** the `FrameStats` struct SHALL have a generated reader that replaces hardcoded byte offsets

#### Scenario: FrameStats struct reader is generated
- **WHEN** the schema contains a `FrameStats` struct with field offsets
- **THEN** `structs.ts` SHALL contain a `FrameStatsStruct` reader
- **AND** `FrameStatsStruct.read(ptr)` SHALL return a typed object with all fields
- **AND** the reader SHALL NOT use hardcoded byte offsets

#### Scenario: Codegen fails if schema is missing
- **WHEN** `bun run build:codegen` is executed and `target/moontui-schema.json` does not exist
- **THEN** the script SHALL exit with error code 1
- **AND** print "Schema file not found. Run `cargo build` first."

#### Scenario: Codegen throws on unknown FFI types
- **WHEN** `scripts/generate-ffi.ts` encounters a type in the schema that is not in `FFI_TYPE_MAP`
- **THEN** the script SHALL throw an error with the unknown type name
- **AND** it SHALL NOT silently fall back to `FFIType.ptr`

### Requirement: defineStruct runtime reads/writes structs from native memory
A `src/struct-helpers.ts` module SHALL provide a `defineStruct(fields)` function that returns a reader/writer for native structs.

#### Scenario: defineStruct reads a struct from a pointer
- **WHEN** `FrameStatsStruct.read(statsPtr)` is called
- **THEN** it SHALL return a typed object with all fields read from the correct offsets
- **AND** the caller SHALL NOT need to know byte offsets or use `DataView` directly

#### Scenario: defineStruct handles all primitive types
- **WHEN** a field has type `f64`, `u64`, `u32`, `u16`, `u8`, `bool`, or `ptr`
- **THEN** `readField` SHALL use the correct `DataView` method and byte size

#### Scenario: defineStruct respects little-endian byte order
- **WHEN** any field is read from native memory
- **THEN** `DataView` SHALL use little-endian (`true` for the littleEndian parameter)

### Requirement: Build pipeline integrates codegen
The build pipeline SHALL run codegen as part of the standard build process.

#### Scenario: bun run build runs codegen
- **WHEN** `bun run build` is executed from the repo root
- **THEN** it SHALL run `bun run build:codegen` before `bun run build:lib`
- **AND** `build:codegen` SHALL run `bun scripts/generate-ffi.ts`

#### Scenario: codegen is idempotent
- **WHEN** `bun run build:codegen` is executed twice without schema changes
- **THEN** the generated files SHALL be identical (no diff)

### Requirement: Generated files are marked as auto-generated
Generated files SHALL have a header comment and `.gitattributes` marking.

#### Scenario: ffi.ts has auto-generated header
- **WHEN** `ffi.ts` is generated
- **THEN** line 1 SHALL be `// AUTO-GENERATED by scripts/generate-ffi.ts — DO NOT EDIT`

#### Scenario: structs.ts has auto-generated header
- **WHEN** `structs.ts` is generated
- **THEN** line 1 SHALL be `// AUTO-GENERATED by scripts/generate-ffi.ts — DO NOT EDIT`

#### Scenario: GitHub collapses generated file diffs
- **WHEN** a PR modifies generated files
- **THEN** `.gitattributes` SHALL mark `ffi.ts` and `structs.ts` as `linguist-generated=true`

## Invariants

- The schema.json is the single source of truth for the FFI boundary.
- Generated code produces identical machine code to hand-written wrappers.
- `defineStruct` is used only on cold paths (stats, callbacks). Hot path (buffer operations) passes raw pointers.
- Manual functions (`@ffi_manual`) are included in the schema but not auto-generated.
- The proc-macro does not modify the developer's source code — it only generates side effects (schema file) and injects new items (extern "C" functions).

### Requirement: Schema function keys are unique FFI names
The generated schema SHALL key exported functions by `ffi_name`, and SHALL retain the Rust method/function name as metadata.

#### Scenario: Duplicate Rust method names across receivers
- **WHEN** two exported methods have the same Rust name but different receivers and different FFI names
- **THEN** both functions SHALL appear in `target/moontui-schema.json`
- **AND** neither SHALL overwrite the other

#### Scenario: Duplicate FFI export name
- **WHEN** two exported functions resolve to the same `ffi_name`
- **THEN** schema generation SHALL fail with a diagnostic naming the duplicate export

### Requirement: Schema type mapping is fail-fast
The Rust schema emitter SHALL map all supported FFI scalar types explicitly and reject unsupported types instead of silently treating them as pointers.

#### Scenario: Supported scalar type is exported
- **WHEN** an exported function uses `i32`, `u64`, `usize`, `f64`, or `bool`
- **THEN** the schema SHALL record the explicit scalar type
- **AND** the generated TypeScript definition SHALL use the corresponding `FFIType`

#### Scenario: Unsupported type is exported
- **WHEN** an exported function or struct field uses an unsupported type
- **THEN** schema generation SHALL fail
- **AND** it SHALL NOT emit `ptr` as a fallback

### Requirement: Codegen writes generated files atomically
The TypeScript codegen script SHALL write generated files through a temporary file, validate or format that file, and then replace the destination atomically.

#### Scenario: Formatter fails during codegen
- **WHEN** formatting generated output fails
- **THEN** `bun run build:codegen` SHALL exit non-zero
- **AND** the existing generated file SHALL remain unchanged

#### Scenario: Codegen formatting scope
- **WHEN** `bun run build:codegen` runs
- **THEN** it SHALL format only generated outputs
- **AND** it SHALL NOT run unsafe formatting across unrelated repository files

### Requirement: API grouping and callbacks are schema-driven
The generated TypeScript API grouping and callback factories SHALL be derived from schema metadata rather than hardcoded receiver names or function-name whitelists.

#### Scenario: Unknown API group
- **WHEN** the schema contains an exported function without a known API group
- **THEN** codegen SHALL fail with a clear error
- **AND** it SHALL NOT silently route the function to the renderer API

#### Scenario: New callback descriptor
- **WHEN** a callback signature is added to the schema
- **THEN** codegen SHALL generate the callback factory from the descriptor
- **AND** no hand-written `ffiContent +=` block for that callback SHALL be required

### Requirement: 64-bit numeric return mapping is explicit
Generated TypeScript wrappers SHALL treat `u64` and `i64` values as `bigint` unless a wrapper explicitly normalizes them to a checked `number`.

#### Scenario: Generated u64 return
- **WHEN** a generated wrapper returns `u64`
- **THEN** its TypeScript return type SHALL be `bigint`
- **OR** the wrapper SHALL perform an explicit safe-range conversion before returning `number`
